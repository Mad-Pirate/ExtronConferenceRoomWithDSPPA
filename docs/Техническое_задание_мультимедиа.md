# ТЕХНИЧЕСКОЕ ЗАДАНИЕ
## на создание систем мультимедийной поддержки и автоматизированного управления ими
### Здание Аппарата Управления АО «Черномортранснефть» (ПК «Шесхарис»)

**Основание:** проект «14.3.17-КРПО/17 "ПК «ШЕСХАРИС». ЗДАНИЕ АППАРАТА УПРАВЛЕНИЯ. СТРОИТЕЛЬСТВО". РАБОЧАЯ ДОКУМЕНТАЦИЯ. КЗП. ТЕХНОЛОГИЯ КОНФЕРЕНЦ-ЗАЛА, ПЕРЕГОВОРНЫХ. СИСТЕМА ВИДЕОКОНФЕРЕНЦСВЯЗИ».

**Исполнитель:** ЗАО «ЭнергоСтрой».

> *Примечание. Настоящее ТЗ реконструировано на основе двух итоговых документов проекта — «Инструкции пользователя (оператора) системы управления средствами мультимедийной поддержки Селекторной» и «Технического отчёта. Наладка систем мультимедиа здания Аппарата Управления». Требования извлечены из описания фактически реализованной и сданной системы.*

## 1. Общие сведения

### 1.1 Назначение
Система предназначена для технической (мультимедийной) поддержки мероприятий в помещениях здания Аппарата Управления: проведения видеоконференцсвязи, презентаций, совещаний, просмотра ТВ, а также для записи мероприятий и автоматизированного управления всем комплексом оборудования силами одного оператора.

### 1.2 Состав объектов автоматизации
Система должна охватывать следующие группы помещений, каждая со своим управляющим процессором:
1. Кабинеты руководителей (в т.ч. 5.003, 5.008, 5.013, 5.034).
2. Переговорная 2.011.
3. Переговорная 2.060.
4. Конференц-зал 4.035 / Аппаратная 5.037.
5. Селекторная 5.016.

### 1.3 Этапность работ
Наладка выполняется в четыре этапа: кабинеты руководителей → переговорные → конференц-зал → селекторная.

### 1.4 Основания для отступлений от проекта
Допускаются обоснованные отступления от запроектированных схем вследствие:
- отказа Заказчика от врезных настольных лючков со сматывателями;
- выявленных ошибок в проектных схемах;
- оптимизации функционирования оборудования под нужды Заказчика;
- изменений, вносимых Заказчиком.
Все отступления подлежат документированию в техническом отчёте.

## 2. Требования к интерфейсу пользователя

### 2.1 Общие требования
- Интерфейс разрабатывается в соответствии с рекомендациями производителя (Extron GUI Design).
- Цветовое решение базируется на основном цвете `#005D9E`, близком к корпоративному.
- Интерфейс должен быть простым для восприятия, выполнен в комплементарных цветах, кнопки сгруппированы по функциональным, логическим и управляющим признакам.
- Управление осуществляется через сенсорную панель (TLP Pro / планшет с ПО Extron Control) и/или веб-интерфейс процессора управления.

### 2.2 Цветовая палитра (фрагмент — ключевые элементы)
| Элемент | Цвет (HEX) |
|---|---|
| Граница кнопки | 00FC89 |
| Заполнение/активная кнопка №1 | 10C774 |
| Пассивная (заблокированная) кнопка | A9A9A9 |
| Надпись | FFFFFF |
| Аварийное сообщение | ED6132 |
| Активная часть ползунка | 10C774 |
| Неактивная часть ползунка | 696969 |

### 2.3 Структура экранов
Интерфейс должен содержать следующие типы страниц:
- **Стартовая** — система «выключена»; индикация управляемости устройств, кнопка включения.
- **Главная** — ожидание команд: кнопки запуска задач, оперативного управления, настроек, регулировки громкости/mute, индикатор уровня звука.
- **Страницы задач** — управление в рамках запущенной задачи.
- **Страницы оперативного управления** — единообразное управление общими устройствами из разных задач.
- **Страницы настроек** — изменение параметров (доступ по паролю).
- **Страница сообщений/ошибок** — информация о состоянии управляемых устройств.

### 2.4 Способы информирования пользователя
- изменением цвета кнопок (зелёный — вкл/активно, красный — выкл/аварийно, серый — заблокировано);
- текстовыми надписями;
- заполнением ползунковых индикаторов;
- световым индикатором на панели (медленное мигание красным — наличие сбоя).

## 3. Функциональные требования — «Задачи»

Для упрощения управления применяется концепция **«Задача»** — управляющий процесс, выполняющий одну пользовательскую функцию. Одновременно может выполняться только одна задача; кнопки прочих задач блокируются (переменная `Running_State`).

Перечень задач (на примере Селекторной):
1. **SKYPE** — ВКС через ПО (Skype и аналоги).
2. **Polycom местный** — ВКС через местный видеокодек Poly RPG 700 (с функцией трансляции контента в канал).
3. **Polycom Москва** — ВКС через московский видеокодек.
4. **Презентация** — демонстрация контента (ПК руководителя, ПК оператора, делегаты, ShareLink).
5. **Оперативное совещание** — совещание без ВКС.
6. **ТВ** — просмотр телепередач.

### 3.1 Общие требования к запуску задачи
При запуске любой задачи (кроме «ТВ») система должна:
- очистить все соединения видеокоммутатора **до** установки новых (исключение влияния ручных команд с лицевой панели/ПО);
- выполнить коммутацию видео согласно задаче;
- сделать центральную видеокамеру текущей и вызвать пресет №1 (место Председателя);
- включить звук в динамиках, установить предопределённые уровни в аудиопроцессоре;
- выключить звук потолочных микрофонов;
- подготовить систему записи;
- для задач Polycom — дать команду видеокодеку включить передачу звука в канал.

### 3.2 Общие требования к завершению задачи
При нажатии «Завершить» система должна: разорвать все аудио/видео соединения, выключить звук в динамиках (для Polycom — и передачу в канал), восстановить штатную коммутацию мониторов (ПК ВКС, ПК оператора, ПК руководителя), показать главную страницу.

### 3.3 Блокировки
- Запуск задачи невозможен при активной другой задаче.
- Невозможна подача команды, способной привести к аварийному останову выполняемой задачи (функциональная блокировка).

## 4. Требования к оперативному управлению

Оперативное управление должно быть доступно из любой задачи и включать:

### 4.1 Управление видеокамерами
- Выбор камеры (левая/центральная/правая), индикация активной камеры.
- Управление по пресетам и ручное позиционирование (кнопки направления + выбор скорости 0–3).
- Кнопка «Соединить выбранную камеру» (поведение зависит от задачи: монитор оператора / ПК ВКС / местный кодек / скалер).
- Кнопка «Автоповорот» — автоматический вызов пресета по включённому настольному микрофону с задержкой ~3 с на позиционирование и последующим соединением.
- Спецстраницы «Докладчик у стены» и «Докладчик у окна» — быстрое позиционирование на общий вид гостевой зоны + управление потолочным микрофоном.

> Для видеокамер без собственной памяти пресетов (Polycom EagleEye IV) пресеты реализуются макросами процессора управления.

### 4.2 Управление микрофонами
- Включение/выключение настольных, потолочных микрофонов и гарнитуры оператора (зелёный — вкл, красный — выкл).
- Пошаговая регулировка уровней с текстовыми и полосковыми индикаторами, индикацией включения.
- Кнопка **«Приглушить звук на 2 сек»** — гашение акустической петли (mute динамиков на 2 с).

### 4.3 Управление уровнями звука и подзвучкой
- Регулировка уровней потолочных/настольных микрофонов, входного канала контента (HDMI), громкости динамиков, подзвучки, сигнала от ПК ВКС.
- Два независимых тракта от микрофонов: в канал ВКС и на подзвучку, с собственными регулировками.

### 4.4 Вывод на контрольный монитор
- Вывод на монитор оператора источников: камеры (Лев/Центр/Прав), POLY ЧТН, POLY МСК, ОП ПК; кнопка отключения вывода.

### 4.5 Трансляция контента в канал (только «Polycom местный»)
- Выбор источника (ПК ВКС, ПК БОСС, ПК Оператора, ПК Делегата) и кнопка «Выключить».

### 4.6 Управление записью
- Старт/пауза/стоп записи, индикатор оставшегося времени; задержка ~5 с перед стартом.
- Запись доступна при любой задаче, кроме «ТВ».

## 5. Требования к подсистеме записи

- Устройство записи: Extron SMP 352.
- Настраиваемые параметры: раскладка видеовходов (рекомендуется «Fullscreen A»), разрешение (рекомендуется 720p; возможны 480p/1080p/Custom), режим записи (видео / видео+звук), место записи (АВТО, USB перед./задн., внутренний накопитель), контроль свободного места.
- Канал «A» — источник медиаэкрана, канал «B» — видеокамеры.
- Уровень сигнала на входе SMP 352 устанавливается оптимальным и не предназначен для оперативного изменения.

## 6. Требования к обработке и коммутации звука

### 6.1 Архитектура
- Основное устройство обработки — аудиопроцессор Biamp Tesira (Forte DAN VT / Server IO в зависимости от помещения); в ряде помещений дополнительно встроенный аудиопроцессор Extron DTP Crosspoint и/или цифровой микшер Yamaha TF5.
- Звук от источников HDMI выделяется на Extron DTP Crosspoint и передаётся на аудиопроцессор Tesira.
- Цифровая аудиосеть **DANTE** с автоназначаемыми адресами `169.254.0.0/16`.

### 6.2 Тракт микрофонов
Эхокомпенсатор → фильтр (полоса 100 Гц – 8000 Гц) → подавитель возбуждения → эквалайзер (настройка на резонансные частоты помещения) → регулятор уровня → микрофонный микшер → компрессор → главный микшер. Эхокомпенсация включается только на микрофонных входах.

### 6.3 Противодействие акустической петле (самовозбуждению)
- При включении любого микрофона громкость ближайшего динамика снижается (на 10 дБ — в Селекторной по инструкции; в технической реализации — на 10 дБ по «зонам влияния»).
- Реализуется через примитив регулятора уровня и команды процессора управления с анализом включённых микрофонов в «зоне влияния».
- При выключении последнего микрофона зоны уровень восстанавливается в 0 дБ.

## 7. Требования к коммутации видео

- Видеокоммутатор: Extron XTP Crosspoint / DTP Crosspoint (по помещениям).
- Коммутация выполняется **только** по командам управляющего процессора; перед новой коммутацией все соединения очищаются.
- В конференц-зале — поддержка видеопроцессора (TVOne CORIOmaster mini) с функциями PIP и FLIP, набор пресетов расположения окна (PIP_UP_LF/DN_LF/UP_RT/DN_RT).
- Поддержка наложения логотипа Заказчика (Alpha Key) в скалере.
- Коммутация USB через Extron USB Plus Matrix Controller по командам процессора.

## 9. Требования к режимам включения/выключения

### 9.1 Холодный старт/перезагрузка (инициализация)
Скрипт первичной инициализации должен: показать стартовую страницу, закрыть все окна панели, разорвать все соединения видеокоммутатора, выключить микрофоны и заглушить источники звука, установить начальные параметры записи, (для конференц-зала — переключить маршрутизацию звука через Tesira Server и проверить успешность), перевести усилители в Stand By и установить уровень 0 дБ, показать готовность к работе.
**Время готовности:** 2–3 мин (конференц-зал — 3,5–4 мин).

### 9.2 Включение
Включение медиаэкрана, показ главной страницы, блокировка кнопок задач на время, восстановление USB-соединений, включение усилителей с MUTE и уровнем 0 дБ, разблокировка задач. Перед включением оператор обязан убедиться в отсутствии сбоев.

### 9.3 Выключение
Запрос подтверждения (Да/Нет), очистка всех аудио/видео соединений, установка таймера неактивности панели (5 мин), показ стартовой страницы.

## 10. Требования к мониторингу управляемости и обработке сбоев

### 10.1 Механизм «мониторов»
- Централизованный мониторинг проектом не предусмотрен; реализуется набор «мониторов» — периодически выполняемых разделов программного кода, опрашивающих состояние драйверов (`CONNECTED`/`DISCONNECTED`) каждого управляемого устройства.
- Отображение сбоя: надпись на стартовой странице, на странице «INFO», на странице ошибок; изменение цвета соответствующей надписи на красный.

### 10.2 Оперативная индикация
- Пара мониторов `Error Active` / `No Errors (Error Inactive)` управляет световым индикатором панели: при сбое — «медленно мигать красной полосой», при норме — «выключить полосу».
- Для устройств, допускающих штатное отключение (напр., аудиомикшер Yamaha), световая авария не формируется.

### 10.3 Выявление неисправностей (порядок для оператора)
1. Проверить индикацию панели (мигание красным). 2. Проверить индикацию на стартовой странице. 3. С ПК оператора проверить сетевую связность (ping по плану IP). 4. Проверить электропитание. 5. Проверить разъёмы управляющих кабелей. 6. Обратиться в техподдержку.
- Учитывать: на выявление сбоя/восстановление процессору требуется до 60 с.
- Таблица типовых неисправностей (признаки/действия) по основным устройствам (процессор IPCP, SMP 352, XTP, Tesira, SHURE DIS-CCU, EagleEye IV, Poly RPG 700) входит в эксплуатационную документацию.
